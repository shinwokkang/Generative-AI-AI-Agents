# Lesson 3.5: 에이전트 디자인 패턴 (Agentic Design Patterns) 📐

이 레슨에서는 복잡하고 예측하기 어려운 자율 AI 에이전트 시스템을 프로덕션 수준으로 신뢰성 있게 구축하기 위해 활용되는 **5대 핵심 에이전트 디자인 패턴**의 개념과 워크플로우 작동 원리를 학습합니다.

---

## 1. 계획 (Planning) 패턴

**계획(Planning) 패턴**은 최종 목표를 달성하기 위해 에이전트가 동적으로 수행할 **'일련의 행동 단계를 사전에 쪼개고 전략적으로 수립'**하는 디자인 패턴입니다.

![Planning Pattern](images/Planning.png)

### ⚙️ 핵심 작동 메커니즘
* **계획 다듬기 (Plan Refinement):** 각 단계의 태스크가 실행될 때마다 그 결과 피드백을 수용하여, 다음 계획을 동적으로 변경 및 다듬어 나갑니다.
* **관심사의 분리 (Separation of Concerns):**
  * **플래너 에이전트 (Planner):** 거시적인 전략 및 할 일 목록(Task List)을 생성 및 업데이트하는 역할.
  * **작업 실행자 에이전트 (Task Executor):** 분배받은 개별 노드에서 도구를 사용하여 업무를 조용히 구현하는 역할.

---

## 2. 성찰 (Reflection) 패턴

**성찰(Reflection) 패턴**은 에이전트가 완성한 결과물을 즉시 사용자에게 반환하지 않고, 리뷰어 역할의 다른 노드를 거쳐 **'자가 평가(Self-Evaluation)'** 및 수정을 거듭하여 품질을 보장하는 패턴입니다.

![Reflection Pattern](images/Reflection.png)

### ⚙️ 핵심 작동 메커니즘
* **루프(Loop) 구조:** `생성 에이전트`가 작성한 초안을 `성찰 에이전트`가 검수하고 개선안 피드백을 전달합니다. 생성 에이전트는 피드백을 반영해 품질 기준에 도달하거나 최대 반복 수에 도달할 때까지 결과 개선 과정을 반복합니다.
* **성찰의 3대 목적:** 
  1. **재계획(Replanning):** 실패 사례 피드백을 바탕으로 전략 수정.
  2. **탐색(Search):** 기존 방식이 막혔을 때 대안 경로 탐색.
  3. **평가(Evaluation):** 기준 미달의 초안 필터링 및 교정.

---

## 3. 맵리듀스 (Map-Reduce) 패턴

**맵리듀스(Map-Reduce) 패턴**은 하나의 큰 작업을 여러 개의 작은 작업으로 병렬 쪼개어 동시 처리(Map)하고, 최종 결과를 하나로 응집력 있게 수집/가공(Reduce)하는 패턴입니다.

![Map-Reduce Pattern](images/Map-Reduce.png)

### ⚙️ 핵심 작동 메커니즘
* **맵(Map) 단계:** 보고서 작성 태스크를 섹션 A, B, C로 나누어 여러 독립 에이전트(Section Writers)가 병렬로 동시 작성하여 효율을 극대화합니다.
* **리듀스(Reduce) 단계:** 분할 작성된 결과를 수집하여 한 편의 유기적인 문서(Write Final Report)로 병합합니다.
* **LangGraph의 솔루션:** 조건부 에지와 **`Send` API**를 사용하여 처리할 노드의 개수를 사전에 알지 못해도 동적인 팬아웃(Fan-out) 처리를 지원하며, 중첩된 **서브그래프(Subgraphs)**로 관리합니다.

---

## 4. 다중 에이전트 (Multi-Agent) 아키텍처 패턴

각각의 도구와 언어 모델로 무장한 전문성 있는 다수 에이전트가 공통 목표를 향해 협력하는 구조입니다.

![Multi-Agent Pattern](images/Multi-Agent.png)

### ⚙️ 핵심 작동 메커니즘
* **감독 에이전트 (Supervisor Agent):** 팀의 PM(프로젝트 매니저) 역할을 하며, 입력된 태스크를 분석해 각 영역의 전문 에이전트(Agent 1, 2, 3)에게 분배하고 관리합니다.
* **이점:** 여러 작업의 동시 병렬 수행이 가능해 연산 시간을 단축시키며, 에이전트 개별 전공 영역에만 집중하므로 예외 대응 능력이 향상되어 전체 시스템이 견고해집니다.

---

## 5. 인간 참여형 (Human-in-the-loop) 4대 패턴

에이전트의 완전 자율 실행에 제동을 걸어, 안전한 비즈니스 룰을 지키기 위해 활용하는 인간 개입 패턴입니다.

### ① 승인 워크플로우 (Approval Workflows)
에이전트가 다음 행동(예: 데이터베이스 쓰기, 금융 결제)을 계획하면 실행 전에 사용자에게 보고하고 진행 신호(Go-ahead)가 떨어질 때까지 대기합니다.

![Approval Pattern](images/Approval.png)

---

### ② 입력 대기 (Wait for Input)
에이전트가 미비한 필수 정보(사용자의 상세 예산, 여행 희망일 등)가 있음을 자각했을 때, 상태를 일시정지하고 적극적으로 사용자에게 입력을 구합니다.

![Wait for Input Pattern](images/Wait_for_Input.png)

---

### ③ 타임 트래블 (Time Travel)
에이전트가 지나왔던 과거 시점(예: 2단계)의 상태 스냅샷으로 되감기(Rewind)를 하여 데이터를 수정한 후, 수정한 상태 지점으로부터 새로운 흐름의 실행 결과를 분기 생성하여 결과를 시뮬레이션합니다.

![Time Travel Pattern](images/Time_travel.png)

---

### ④ 도구 호출 리뷰 (Review Tool Calls)
에이전트가 외부 시스템과 상호작용하는 도구 API를 실제로 기동하기 전에, 어떤 데이터를 보내려고 하는지 초안을 먼저 사용자 화면에 띄우고(예: 메일 본문 리뷰) 최종 허가를 득한 뒤 발송합니다.

![Review Tool Calls Pattern](images/Review_tool_calls.png)
